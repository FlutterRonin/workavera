# Reading 产品需求文档

[English](./reading-prd.md)

> 实现基线：Workavera `0.2.0`，于 2026-10-29 按提交 `7d8d88d` 核验。Reading 于 `0.0.1` 上线。

## 1. 产品目的

Reading 是 Workavera 的稍后读模块。它保存用户想回头再看的链接——文章、代码仓库、产品页面——连同笔记、标签、阅读状态和 AI 总结，并允许把链接关联到 Board 项目，让调研资料和它服务的工作放在一起。

## 2. 目标

- 保存、编辑、归档、恢复和删除私有的稍后读条目。
- 用未读、已读、已归档三种状态跟踪条目，并支持一键全部标为已读。
- 用自由标签和可选的 Board 项目组织条目。
- 最多置顶 6 个未归档的条目。
- 抓取条目页面，并用用户的默认模型按指定语言生成总结和要点。
- 让 Chat 搜索、阅读、保存、更新和总结稍后读条目。

## 3. 非目标

- 与其他用户共享稍后读条目，或公开发布它们。
- 保存页面的离线副本、截图或 PDF。
- 抓取需要登录的页面，或渲染只能靠 JavaScript 显示的页面。
- 在文章内做高亮、批注或记录阅读进度。

## 4. 数据模型

### `reading_items`

| 字段 | 规则 |
| --- | --- |
| `owner` | 必填，关联用户；创建时设置，之后不可更改。 |
| `url` | 必填，最长 2,048 个字符。 |
| `title` | 必填，最长 240 个字符。 |
| `description` | 可选，说明这个链接为什么重要，最长 4,000 个字符。 |
| `tags` | 可选，字符串组成的 JSON 列表。 |
| `project` | 可选，关联 Board 项目。 |
| `status` | `unread`（默认）、`read` 或 `archived`。 |
| `pinned` | 布尔值；每位用户最多置顶 6 个未归档条目。 |
| `content_text` | 抓取或粘贴的正文，最大 256 KiB。 |
| `summary` | AI 生成或手写的总结，最大 64 KiB。 |
| `key_points` | 要点组成的 JSON 列表。 |
| `summary_language` | 总结使用的语言，最长 100 个字符。 |

## 5. 行为

- 新增条目需要 URL 和标题；描述、标签、项目、状态、总结语言、总结、要点和正文都可以手动填写。
- 归档条目会取消置顶。已归档条目离开主列表，进入单独的归档列表，可在其中恢复或删除。
- 置顶第 7 个未归档条目会被拒绝，并给出明确提示。
- "全部标为已读"在一个事务中把该用户所有未读条目改为已读。
- 总结时会抓取页面（最大 1 MiB）并提取可读文本；如果是 GitHub 仓库页面，则读取仓库的 README，而不是页面框架。正文、总结和要点都会保存到条目上。生成总结需要配置了 API Key 的默认模型；没有时，用户会被告知文章已抓取但无法总结。

## 6. 用户体验

- Reading 位于 `/reading`，左侧是列表，右侧是选中条目的详情——总结、要点和正文。
- 置顶条目排在最上方，其余按最近更新时间排序。列表支持搜索，并可按状态和项目过滤。
- 通过**添加链接**对话框新增条目，之后可以在列表和详情中编辑、置顶、归档或删除。
- 总结条目前会先请求确认，因为这会抓取页面并调用模型。

## 7. 权限

- 稍后读条目是私有的：只有所有者可以列出、查看、创建、更新或删除，且所有者不可更改。
- 创建条目时不能直接置顶；置顶必须经过置顶规则，以保证 6 个的上限。
- 页面由服务端以 `Workavera/1.0` 的 User-Agent 抓取，有大小限制，且只抓取用户保存的 URL。

## 8. 助手工具

### `reading_search`

按标题、URL、描述或标签搜索用户的条目，可按状态和项目过滤。最多返回 20 条（默认 10 条），包含总结和要点，但不包含正文。

### `reading_get`

按 ID 返回单个条目；只有明确要求时才包含正文。

### `reading_upsert`

一次创建或更新 1 到 50 个条目。创建需要 URL 和标题；更新只修改传入的字段。用于保存链接、修改状态、编辑标题或更新标签。

### `reading_summarize`

抓取条目页面，并用用户的默认模型生成总结。已有总结的条目直接返回现有总结，不会重新抓取。

这些工具同样可以通过 API Key 提供给 MCP 客户端，见 [MCP 接入 PRD](./mcp-server-prd.zh-CN.md)。

## 9. 验收标准

1. 用户可以新增、编辑、归档、恢复和删除自己的稍后读条目，其他用户都看不到。
2. 置顶第 7 个未归档条目会失败；归档已置顶的条目会取消置顶。
3. "全部标为已读"之后，该用户没有未读条目。
4. 总结一篇可访问的文章时，会按所选语言保存正文、总结和要点；没有可用的默认模型时，用户会收到说明原因的错误。
5. GitHub 仓库链接根据其 README 生成总结。
6. Chat 可以在用户自己的列表内查找、阅读、保存、更新和总结条目。
