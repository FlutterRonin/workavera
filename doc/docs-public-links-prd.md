# Public Document Links Product Requirements Document

[简体中文](./docs-public-links-prd.zh-CN.md)

> Implementation baseline: Workavera `0.2.0`, verified against commit `7d8d88d` on 2026-10-29. Public document links shipped in `0.1.0`; opening a link in a new tab and opening documents from public project timelines were added in `0.1.1`.

## 1. Purpose

Public document links let the creator of a [Docs](./docs-prd.md) document publish one revision of it to an unguessable link that anyone can read without an account—a proposal for a client, a guide for readers outside the team—while editing continues privately in the workspace.

## 2. Goals

- Let a document's creator publish it to a public link, optionally with an expiry date.
- Serve the revision that was published, so later edits stay private until the creator publishes again.
- Let the creator see which revision is public, republish the latest one, change or clear the expiry, and revoke the link.
- Make a link stop working at once when it is revoked, expires, or its document is archived or deleted, without revealing which.
- Give readers a clean page: Markdown with a progress bar and an outline, HTML in the editor's sandbox.
- Expose only the attachments the published revision references.

## 3. Non-goals

- Links that follow the live document, are guessable, can be listed, or accept comments and edits.
- Publishing by project members other than the creator, or by the assistant.
- Password-protected links, view counts, or analytics.
- More than one link per document.
- Custom domains or paths for public pages.

## 4. Data model

### `doc_shares`

| Field | Rule |
| --- | --- |
| `doc` | Required, unique relation to the document; deleted with it. |
| `slug` | Unique 22-character lowercase alphanumeric public identifier, generated by the server. |
| `revision` | The published revision, read from `doc_versions`. |
| `expires` | Optional; empty means the link does not expire. |
| `created_by` | The creator who published. |

A share is a separate record, so publishing, expiring, and revoking never touch the document and never create a revision. Owners read their own shares through PocketBase list and view rules; every write goes through the Docs API, so a client can neither choose a slug nor pin a revision by hand.

## 5. Behavior

- Publishing a document that has no link creates one at its current revision.
- Publishing again with **republish** moves the link to the current revision; changing only the expiry never moves it.
- Revoking deletes the share, so publishing again issues a new slug instead of reviving the old link.
- A link is unavailable when its slug is unknown, it has expired, or its document is archived or deleted. All of these answer alike.
- An attachment is served through the link only when the published revision's content references it; attachments uploaded afterwards stay private.

## 6. User experience

- The creator shares from the document toolbar. The dialog creates the link, copies it, opens it in a new tab, shows the published revision against the current one, publishes the latest revision on request, sets or clears an expiry, and revokes.
- A shared document opens at `/s/{slug}` outside the signed-in app, with no page chrome around the document: its own heading is the page's, and its title only names the browser tab. An unavailable link says only that it is unavailable.
- Shared Markdown renders read-only with a scroll progress bar across the top and, on wide screens, an outline of its headings that highlights the current section and jumps to any of them. Shared HTML renders in the same sandboxed opaque origin as the editor preview, without either aid.
- A [public project timeline](./board-public-preview-prd.md) opens a task's linked documents through their own public links, and names but does not open documents that have none.

## 7. HTTP API

- `GET /api/docs/{id}/share` returns the document's current link, if any.
- `POST /api/docs/{id}/share` publishes, changes the expiry, or republishes.
- `DELETE /api/docs/{id}/share` revokes the link.
- `GET /api/public/docs/{slug}` returns the published title, kind, content, revision, and publication time.
- `GET /api/public/docs/{slug}/assets/{assetId}` serves an attachment the published revision references.

The two public routes are the only ones an anonymous visitor may reach. Owner, project, folder, and editor identities never leave the server. They are custom endpoints because built-in rules cannot resolve a slug into another collection's record, apply expiry, and strip private fields, and attachments are proxied per slug because protected files need a file token no anonymous visitor can obtain.

## 8. Permissions

- Only the document's creator can publish, republish, set an expiry on, or revoke its link, matching archive and delete. Project membership grants no sharing rights.
- The assistant has no tools for public links.

## 9. Acceptance criteria

1. The creator can publish, copy, open, republish, set and clear an expiry on, and revoke a link; nobody else can.
2. An anonymous visitor sees the published revision, its title, and its referenced attachments, and nothing about the owner, project, or folder.
3. Edits after publishing stay private until the creator republishes, and changing the expiry does not republish.
4. A revoked, expired, archived, or deleted document's link answers as unavailable, without revealing which; publishing after revoking gives a new link.
5. An attachment uploaded after publishing is not reachable through the link.
6. A public project timeline opens shared linked documents and does not open unshared ones.
