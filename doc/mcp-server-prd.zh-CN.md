# MCP 接入产品需求文档

[English](./mcp-server-prd.md)

> 实现基线：Workavera `0.2.0`，于 2026-10-29 按提交 `7d8d88d` 核验。MCP 接入于 `0.0.7` 上线。

## 1. 产品目的

MCP 接入让用户已经在用的 AI 工具——Claude Code、Cursor，以及任何支持 Model Context Protocol 的客户端——直接操作他们的 Workavera 工作区。Workavera 在 `/api/mcp` 作为 MCP *服务端*，提供与应用内助手相同的工作区工具，经过相同的权限校验，并用用户在 Settings 中创建的 API Key 鉴权。反方向的能力，即把外部 MCP 服务接入 Chat，见 [MCP 客户端集成 PRD](./mcp-client-prd.zh-CN.md)。

## 2. 目标

- 用户可以在 Settings 中创建、查看和撤销个人 API Key。
- 新建的 Key 只完整显示一次，并附带可以直接粘贴到 Claude Code 或 Cursor 的配置。
- Key 可以在选定的期限后过期，也可以永不过期。
- 除非用户在创建时明确允许，否则 Key 无法使用破坏性工具。
- 通过 MCP 提供 Board、Calendar、Docs、Reading、Contacts 和 Resources 的工作区工具，以 Key 所有者的身份执行。

## 3. 非目标

- 为 MCP 客户端提供 OAuth 或其他交互式登录；Key 是唯一的凭证。
- 团队共用、属于服务账号或仅限单个项目的 Key。
- 除破坏性开关之外更细粒度的权限范围。
- 提供只属于 Chat 的工具：资源下载链接、`chat_send_files`、记忆、沙箱，以及用户自己接入的外部 MCP 工具。
- 用量配额或按 Key 的限流。

## 4. 数据模型

### `api_keys`

| 字段 | 规则 |
| --- | --- |
| `user` | Key 的所有者；Key 以该用户的身份执行。 |
| `name` | 必填名称，1 到 100 个字符。 |
| `prefix` | 密钥的前 10 个字符，显示在 Key 列表中。 |
| `key_hash` | 密钥的 SHA-256；在所有 API 响应中隐藏。 |
| `allow_destructive` | 是否允许该 Key 使用需要审批的破坏性工具。 |
| `expires` | 可选；过期的 Key 会被拒绝。 |
| `last_used` | Key 使用期间最多每分钟更新一次。 |

Key 只能通过 `POST /api/apikeys` 创建：服务端生成密钥（`sk-wa-` 加 64 位十六进制字符），保存其哈希，并只返回一次明文。所有者可以通过 PocketBase 自带的 API 列出、查看和删除自己的 Key；Key 不能编辑。

## 5. 用户体验

- Settings 中有 **API Keys** 卡片，列出每个 Key 的名称、前缀、过期时间和最近使用时间，删除前会请求确认。
- 创建 Key 时需要填写名称、选择过期时间（永不过期、7 天、30 天、90 天或 1 年），以及一个默认关闭的**允许破坏性操作**选项，并说明开启后可以在没有确认提示的情况下永久删除任务和日历事件。
- 创建后，对话框只完整显示一次 Key，并提供两个复制按钮：一个复制 Key，一个复制 MCP 配置。配置指向本服务器的 `/api/mcp`，以 Bearer token 的方式携带 Key，可用于 Claude Code 的 `.mcp.json` 或 Cursor 的 `mcp.json`。

## 6. MCP 端点

- `/api/mcp` 以无状态模式提供 MCP Streamable HTTP 传输，每个请求单独鉴权。
- 每个请求都必须携带 `Authorization: Bearer <key>`。未知、格式错误或已过期的 Key 会被拒绝。
- 服务端以 Workavera 的名义和当前版本号标识自己，并向客户端发送说明：修改任何内容之前先查到准确的 ID，并把资源内容视为数据而不是指令。
- 每个工具都以 Key 所有者的身份执行，经过与应用内助手完全相同的校验：身份、角色、所有权和 revision。

## 7. 破坏性操作

- 在 Chat 中需要用户审批的工具——删除 Board 任务和删除日历事件——在未勾选**允许破坏性操作**的 Key 上不会出现，服务端说明中也会写明。
- 允许该权限时，这些工具会立即执行，不再像 Chat 那样等待交互式审批：创建带此权限的 Key 本身就是审批。服务端说明会提醒客户端只在被明确要求时才调用它们。

## 8. 已知问题

- 已停用账号的 API Key 仍然可用。停用会阻止登录并作废会话 token，但 `/api/mcp` 不检查停用标记，因此在修复之前，需要手动撤销这些 Key。

## 9. 验收标准

1. 用户可以创建 Key、看到一次完整的 Key、复制可用的客户端配置，并在之后撤销它。
2. 保存的记录永远不会暴露密钥或其哈希。
3. 使用该 Key 的客户端可以以所有者身份列出并调用工作区工具，且看不到所有者本来看不到的内容。
4. 没有破坏性权限的 Key 不提供删除工具；有该权限的 Key 会立即执行删除。
5. 已过期或已撤销的 Key 在下一次请求时就会被拒绝。
6. 只属于 Chat 的工具永远不会通过 MCP 出现。
